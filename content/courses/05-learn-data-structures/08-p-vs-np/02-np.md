The design team is building a shop bundle. They have a pile of items from the latest
raid, each with a gold value, and they ask: **is there a set of items worth exactly
700 gold?** This is the **subset sum** problem, and it has a strange property.

## Checking is easy

If a teammate hands you an answer, "items 1, 2, 5 and 6", checking it is trivial: add
up four numbers and compare with 700. That's O(n).

## Solving seems hard

Finding the answer yourself is a different story. The obvious approach tries every
possible subset. Each item is either in or out, so n items give **2ⁿ** subsets.

```go
package main

import "fmt"

// verify checks a proposed answer: do the chosen items add up to target? O(n).
func verify(values []int, chosen []int, target int) bool {
	sum := 0
	used := map[int]bool{}
	for _, i := range chosen {
		if i < 0 || i >= len(values) || used[i] {
			return false // out of range or picked twice
		}
		used[i] = true
		sum += values[i]
	}
	return sum == target
}

// solve tries every subset: O(2ⁿ · n).
func solve(values []int, target int) ([]int, int) {
	n := len(values)
	tried := 0
	for mask := range 1 << n { // each bit of mask says "take item i"
		tried++
		var chosen []int
		sum := 0
		for i := range n {
			if mask&(1<<i) != 0 {
				chosen = append(chosen, i)
				sum += values[i]
			}
		}
		if sum == target {
			return chosen, tried
		}
	}
	return nil, tried
}

func main() {
	loot := []int{340, 120, 75, 510, 230, 95, 410, 60} // gold value of each item
	chosen, tried := solve(loot, 700)
	fmt.Println("found:", chosen, "after trying", tried, "subsets")
	fmt.Println("verified:", verify(loot, chosen, 700))

	_, tried = solve(loot, 1)
	fmt.Println("impossible target: tried", tried, "subsets")
}
```

Output:

```
found: [1 2 5 6] after trying 103 subsets
verified: true
impossible target: tried 256 subsets
```

Items 1, 2, 5 and 6 are worth 120 + 75 + 95 + 410 = 700. With 8 items, trying all
256 subsets is instant. But the count doubles with every item: 40 items means about
1.1 trillion subsets, and 100 items would outlast the universe.

The loop uses a neat trick: the numbers 0 to 2ⁿ − 1, written in binary, are exactly
all the in/out patterns for n items. `1 << n` is 2ⁿ, and `mask&(1<<i) != 0` asks
"is bit i set?", meaning "is item i in this subset?".

Cleverer algorithms exist (dynamic programming solves it quickly when the gold values
are small), but for large values nobody knows an algorithm that's polynomial in the
input size.

## The class NP

**NP** is the class of decision problems where a "yes" answer comes with a
**certificate** (a proof, a witness) that can be **verified in polynomial time**. For
subset sum, the certificate is the list of chosen items, and `verify` checks it in O(n).

Don't be fooled by the name. NP stands for **nondeterministic polynomial time**: a
magical machine that could *guess* the right certificate and then verify it would solve
the problem in polynomial time. It does **not** mean "not polynomial".

More NP problems from game development:

- **Sudoku** (generalised to n × n grids): checking a filled grid is easy; filling it
  can be hard.
- **Graph colouring**: can the zones be coloured with 3 colours (say, 3 PvP factions)
  so that no two neighbouring zones share one?
- **Scheduling**: can all these raids fit into the weekend so no player is booked twice?
- **Route planning**: is there a tour of every zone of at most 60 minutes? (That's the
  travelling-salesman problem, coming up soon.)

## P is inside NP

Every problem in P is also in NP. If you can *solve* a problem in polynomial time, you
can verify a claimed answer by just solving it yourself. So P ⊆ NP.

The famous open question is whether that goes the other way too:

> **Does P = NP?** If a solution can be *checked* quickly, can it always be *found*
> quickly?

Almost every computer scientist believes the answer is **no**: some problems really are
harder to solve than to check. But after more than 50 years of trying, nobody has
proved it. It's one of the seven Millennium Prize Problems, and the Clay Mathematics
Institute will pay $1,000,000 for a proof either way.
