  solution: |
    package main

    import (
    	"crypto/ed25519"
    	"encoding/hex"
    	"errors"
    	"fmt"
    )

    func loadSigningKey(seedHex string) (ed25519.PrivateKey, error) {
    	seed, err := hex.DecodeString(seedHex)
    	if err != nil {
    		return nil, err
    	}
    	if len(seed) != ed25519.SeedSize {
    		return nil, errors.New("ed25519 seed must be 32 bytes")
    	}
    	return ed25519.NewKeyFromSeed(seed), nil
    }

    func verifyBundle(pub ed25519.PublicKey, bundle, sig []byte) bool {
    	if len(pub) != ed25519.PublicKeySize {
    		return false
    	}
    	return ed25519.Verify(pub, bundle, sig)
    }

    func main() {
    	priv, err := loadSigningKey("4ccd089b28ff96da9db6c346ec114e0f5b8a319f35aba624da8cf6ed4fb8a6fb")
    	if err != nil {
    		fmt.Println("load:", err)
    		return
    	}
    	sig := ed25519.Sign(priv, []byte{0x72})
    	fmt.Println("signature:", hex.EncodeToString(sig))
    	pub := priv.Public().(ed25519.PublicKey)
    	fmt.Println("verifies:", verifyBundle(pub, []byte{0x72}, sig))
    	fmt.Println("short key:", verifyBundle(pub[:31], []byte{0x72}, sig))
    }

Keybox signs with **Ed25519**, the signature scheme to reach for by default. It's in
`crypto/ed25519`, it has no parameters to get wrong, and it's fast.

## The API

```go
func GenerateKey(random io.Reader) (PublicKey, PrivateKey, error)
func NewKeyFromSeed(seed []byte) PrivateKey
func Sign(privateKey PrivateKey, message []byte) []byte
func Verify(publicKey PublicKey, message, sig []byte) bool
```

- Public keys are **32 bytes**, signatures **64 bytes**.
- `PublicKey` and `PrivateKey` are just `[]byte` types. A `PrivateKey` is 64 bytes: the
  32-byte **seed** followed by the public key. Store only the seed (`priv.Seed()`) and
  rebuild with `NewKeyFromSeed`, which panics if the seed isn't exactly 32 bytes.
- `GenerateKey(nil)` uses `crypto/rand`. Unlike most crypto functions since Go 1.26, a
  non-nil reader *is* used: `GenerateKey` just reads a 32-byte seed from it.
- `Verify` **panics** if the public key isn't 32 bytes. Validate lengths of keys that
  come from outside before calling it.
- `priv.Public()` returns a `crypto.PublicKey` (an `any`); assert it with
  `priv.Public().(ed25519.PublicKey)`.

## Deterministic signatures

Signature schemes built on elliptic curves need a secret per-signature nonce. If it's
ever reused, or even slightly biased, the private key leaks (next lesson has the
famous example). Ed25519 sidesteps the problem: the nonce is a **hash of the private key
and the message**. No randomness is needed at signing time, and the same message
always gets the same signature.

That also makes Ed25519 perfect for **known-answer tests**. RFC 8032 publishes seeds,
public keys, messages and exact signatures:

```go
package main

import (
	"crypto/ed25519"
	"encoding/hex"
	"fmt"
)

func main() {
	seed, _ := hex.DecodeString("9d61b19deffd5a60ba844af492ec2cc44449c5697b326919703bac031cae7f60")
	priv := ed25519.NewKeyFromSeed(seed)
	fmt.Printf("public:    %x\n", priv.Public())
	fmt.Printf("signature: %x\n", ed25519.Sign(priv, nil))
}
```

## Other properties

- **Strong unforgeability.** Go's `Verify` rejects non-canonical encodings, so an
  attacker can't take a valid signature and tweak it into a *different* valid signature
  for the same message. (That kind of malleability caused trouble for Bitcoin with
  ECDSA.)
- **Variants.** `ed25519.Options` selects **Ed25519ctx** (with a context string) or
  **Ed25519ph** (pre-hashed) for use with `priv.Sign` and `VerifyWithOptions`. Plain
  Ed25519 is the common choice; lesson 4 adds context a portable way.
- **Speed.** Tens of thousands of signatures or verifications per second per core.
