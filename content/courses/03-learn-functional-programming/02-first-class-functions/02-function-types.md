  solution: |
    package main

    import (
    	"fmt"
    	"strings"
    )

    type Transform func(string) string

    func (t Transform) Then(next Transform) Transform {
    	return func(s string) string {
    		return next(t(s))
    	}
    }

    func joinAll(steps []Transform) Transform {
    	all := Transform(func(s string) string { return s })
    	for _, step := range steps {
    		all = all.Then(step)
    	}
    	return all
    }

    func addFooter(s string) string {
    	return s + "\n-- generated by Doc2Doc"
    }

    func main() {
    	tidy := Transform(strings.TrimSpace).Then(strings.ToUpper)
    	fmt.Println(tidy("  quarterly report "))

    	publish := joinAll([]Transform{strings.TrimSpace, strings.ToUpper, addFooter})
    	fmt.Println(publish("  annual report "))
    }

Every function in Go has a type, made from its parameter and result types.

```go
func wordCount(s string) int              // type: func(string) int
func replace(s, old, new string) string   // type: func(string, string, string) string
func split(s string) ([]string, error)    // type: func(string) ([]string, error)
```

Parameter *names* aren't part of the type. Only the types and their order count.

## Naming a function type

Writing `func(string) string` everywhere gets noisy. Give it a name:

```go
type Transform func(string) string
```

Now Doc2Doc's code can talk about "a transform" instead of spelling out the
signature. Any function with a matching signature can be used as a `Transform`:

```go
package main

import (
	"fmt"
	"strings"
)

type Transform func(string) string

func applyAll(s string, steps []Transform) string {
	for _, step := range steps {
		s = step(s)
	}
	return s
}

func addFooter(s string) string {
	return s + "\n-- generated by Doc2Doc"
}

func main() {
	steps := []Transform{strings.TrimSpace, strings.ToUpper, addFooter}
	fmt.Println(applyAll("  quarterly report ", steps))
}
```

```text
QUARTERLY REPORT
-- generated by Doc2Doc
```

`strings.TrimSpace` was written years before `Transform` existed, but it still fits,
because its signature matches. A plain `func(string) string` value converts to the
named type automatically when you put it in a `[]Transform`.

## Methods on function types

A named function type is a real type, so it can have methods. The standard library's
most famous example is `http.HandlerFunc`, which you'll meet in Learn HTTP
Servers. Here's a Doc2Doc one:

```go
func (t Transform) Then(next Transform) Transform {
	return func(s string) string {
		return next(t(s))
	}
}
```

With it you can write `Transform(strings.TrimSpace).Then(addFooter)` to build a
new transform from two old ones. You'll dig into that trick in the Function
Transformations chapter.

## Function types and interfaces

A single-method interface and a function type often solve the same problem:

```go
type Formatter interface {
	Format(string) string
}

type FormatFunc func(string) string
```

Go programmers often provide both: the interface for types that carry state, and a
function type with a `Format` method so that a plain function can satisfy the
interface too:

```go
func (f FormatFunc) Format(s string) string { return f(s) }
```

This adapter pattern shows up all over the standard library.
